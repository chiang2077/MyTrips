### 4. 離線可開＋改版後能更新（原編號 #5；兩件綁在一起，缺更新機制就整項不做）

**4a. 離線**：新增 `2026fukuoka/sw.js`，比照 `2026singapore/sw.js`，前綴 `mytrips-2026fukuoka-`，只清自己前綴的舊快取。預先存：`./`、`journal.css`、`autumn.css`（若頁面有用）、`journey.js`、`htb.js`、`manifest.webmanifest`、`icons/*`、`img/*`（頁面實際用到的）、`film.html` 與它的封面圖。**不存** `film/*.mp4`、`film2-ai/*`、`onetake.html`（太大）。
- 封面是 `<iframe src="film.html?embed=1">`：離線時不可以出現瀏覽器的錯誤頁，至少要看得到封面圖或一個乾淨的替代畫面。注意 iframe 也是 navigate 請求——新加坡版「凡是 navigate 一律回 `./`」的寫法在這裡會把首頁塞進 iframe，**要改成依實際網址回對應的快取**。
- 字型來自 Google Fonts，離線時退回系統字型即可，不用存。
- `index.html` 註冊方式比照新加坡版（`location.protocol!=='file:'` 才註冊）；第一次存好跳一次 toast「已存到這支手機，沒網路也能看」。
- 頁面上找個合適位置（頁尾或待辦區）寫一句：QR 車票、地圖、訂票網站仍然要連網。

**4b. 更新機制（使用者明定的條件）**——目標是「以後改了頁面，手機上的舊版一定會換掉，而且不必靠人記得做某件事」：
1. **文字類檔案（頁面、`.css`、`.js`、`manifest`）一律網路優先**：有網路就向伺服器要最新的（fetch 用 `cache:'no-cache'`，避開 GitHub Pages 的 10 分鐘 HTTP 快取），拿到後**順手寫回快取**，所以離線時看到的也是上次連網時的最新版；逾時 4 秒或斷線才用快取。⇒ 就算改版的人忘了換版本號，連上網的手機還是會拿到新內容。
2. **圖片、圖示快取優先**；快取沒有的（新增的圖）抓到後也寫回快取。
3. **版本號產生器** `tools/build_sw.py`：掃 `2026fukuoka/` 該存的檔案，算內容雜湊，重寫 `sw.js` 的 `CACHE` 與 `FILES`；加 `--check` 模式（版本號與現況不符就非零結束，不改檔）。用 `py -3 tools/build_sw.py` 能跑，只用標準函式庫。寫成可指定資料夾，讓新加坡頁以後也能用（但**這次不要動 `2026singapore/`**）。
4. **新版提示**：新的 service worker 接手時（`controllerchange`，且不是第一次安裝），跳一個不會自己消失的提示「有新版行程，點這裡更新」，點了才重新載入（不要自動重載，免得使用者看到一半畫面跳掉）。
5. **手動檢查更新**：頁尾加「檢查更新」鈕＋目前版本（`CACHE` 的雜湊前 7 碼）與最後更新日期。按下去：`registration.update()`、重新抓文字類檔案寫回快取，然後告訴使用者結果（「已是最新」／「已更新，重新載入中」／「現在沒網路」）。沒有 service worker 的環境（`file:`、不支援）要隱藏或停用這顆鈕，不可以報錯。
6. 在 `sw.js` 開頭與 `tools/build_sw.py` 開頭用註解寫清楚「改版後要做什麼」（一句話：改完跑一次 `py -3 tools/build_sw.py 2026fukuoka`；忘了跑，連網的手機仍會更新文字內容，只有換掉同檔名的圖片才一定要跑）。
